# AI 세션 기록 킷

AI 앱(Claude, Codex)과 함께한 작업이 대화창을 닫아도 사라지지 않게 만드는 킷입니다. 세션을 마칠 때 한 마디로 기록을 남기고, 다음 세션이 그 기록을 이어받습니다.

## 왜 필요한가

AI와 일하다 보면 이런 일이 반복됩니다.

- 지난주에 AI와 한참 정리했던 내용을, 새 대화창에서 처음부터 다시 설명하고 있다
- 같은 조사를 또 시키고, 이미 내렸던 결정을 또 고민한다
- "어디까지 했더라?"로 매번 시작한다

대화창이 닫히는 순간 그 안의 맥락은 사라집니다. 이 킷은 **작업을 세션 단위로 기록하고, 다음 세션이 그 기록에서 시작하는 구조**를 만듭니다. 회사 일이든 사이드 프로젝트든 블로그든, "지난번에 뭘 했더라?"가 사라집니다.

## 어떻게 동작하나

```
AI와 작업 ──▶ "세션 종료해줘" ──▶ 내 지식 폴더에 기록
                                   (한 일 · 남은 일 · 과정 메모)

다음 세션 ──▶ "이어서 하자" ──▶ 기록을 읽고 이어서 진행
                │
                └─ 새 작업을 시작하면 과거 기록을 먼저 검색해서 반영
```

기록은 `~/KnowledgeBase`(이하 vault)라는 폴더에 평범한 markdown 파일로 쌓입니다. 메모 앱(Obsidian 등)으로 열어봐도 되고, 그냥 폴더로 둬도 됩니다.

## 준비물

- **Claude 앱(Claude Code) 또는 Codex 앱** — 대화하면서 내 컴퓨터의 파일을 만들고 고칠 수 있는 AI 앱이면 됩니다. 웹 브라우저 전용 챗은 파일을 못 만들어서 해당되지 않습니다.
- Windows, Mac 모두 가능합니다.

## 설치

가장 쉬운 방법은 **AI에게 시키는 것**입니다.

1. 이 폴더(압축을 받았다면 푼 폴더)를 AI 앱에서 엽니다
2. 이렇게 말합니다: **"이 폴더의 setup.sh를 실행해서 킷을 설치해줘"**
3. 설치가 끝나면 — Claude는 새 세션을 열었을 때 "지식베이스 컨텍스트 로딩..."이 잠깐 보이면 성공, Codex는 "이어서 하자"라고 말했을 때 반응하면 성공입니다

터미널이 익숙하면 직접 `bash setup.sh`를 실행해도 됩니다. 스크립트 실행이 안 되는 환경이면 AI에게 **"setup.sh 내용을 읽고 그 단계를 직접 수행해줘"**라고 말하면 됩니다.

여러 번 설치해도 안전하고, 기존 앱 설정을 덮어쓰지 않습니다.

## Claude와 Codex의 차이

스킬(아래 표의 기능들)은 양쪽에 모두 연결됩니다. 다만 자동 실행 장치(훅)는 Claude에만 있습니다.

| | Claude | Codex |
|---|---|---|
| "세션 종료해줘"로 기록 | ✓ | ✓ |
| "이어서 하자"로 복원 | ✓ | ✓ |
| 세션 시작 시 진행 중 작업 자동 로드 | ✓ | ✗ — "이어서 하자"라고 직접 말하면 됩니다 |
| 기록 속 민감정보(연락처·비밀번호 등) 자동 차단 | ✓ | ✗ — 실명·연락처를 쓰지 않는 습관으로 보완 |

## 일상 사용법

외울 것은 하나뿐입니다. **세션을 마칠 때 "세션 종료해줘"라고 말하기.**

- **세션 종료**: "세션 종료해줘" → 오늘 한 일, 남은 일, 시도했다가 접은 것까지 기록됩니다
- **세션 시작**: "이어서 하자" → 지난 기록을 읽고 이어갑니다 (Claude는 진행 중 작업 목록이 자동으로 먼저 떠 있습니다)
- **새 작업**: 자동입니다. AI가 착수 전에 과거 기록을 먼저 검색해서, 예전에 내린 결정이나 했던 조사를 반영합니다
- **주간·월간 돌아보기**: 원할 때 "주간 요약 만들어줘" / "월간 요약 만들어줘"라고 하면 그동안의 기록을 모아 정리해줍니다. 자동으로 돌지 않습니다

## 무엇이 설치되나

| 종류 | 이름 | 역할 |
|---|---|---|
| 스킬 | `session-end` | 세션 종료 시 한 일·남은 일·과정 메모를 기록 |
| 스킬 | `session-start` | 이전 기록을 읽고 이어서 시작 |
| 스킬 | `kb-lookup` | 새 작업 전에 과거 기록을 먼저 검색 |
| 스킬 | `kb-routing` | 기록을 어느 폴더에 둘지, 목차를 어떻게 관리할지 규칙 |
| 스킬 | `weekly-summary` / `monthly-summary` | 주간·월간 요약 — **요청할 때만** |
| 스킬 | `humanize-ko` | 한국어 글의 번역투·상투 표현을 자연스럽게 다듬기 |
| 스킬 | `cognitive-rhythm-writing` | 긴 설명글·블로그 글에 강약과 호흡 만들기 |
| 스킬 | `task-doc-writing` | 여럿이 함께 읽는 작업 문서를 이해하기 쉬운 서술형으로 |
| 훅 (Claude) | `session-context.sh` | 세션이 열릴 때 진행 중 작업·최근 문서를 자동으로 보여줌 |
| 훅 (Claude) | `check-pii.sh` | 기록에 이메일·전화번호·비밀번호류가 들어가면 차단 |
| 스크립트 | `kb_lint.py` | 기록 폴더 건강검진 — 깨진 링크, 목차 누락 등 |

스킬은 AI가 상황에 맞게 알아서 참고하는 지침서입니다. 설치하면 원본이 vault 안 `_kit/` 폴더에 들어가므로, 규칙을 바꾸고 싶으면 AI에게 "session-end 스킬에 ○○ 추가해줘"라고 시키면 됩니다.

## vault(지식 폴더) 구조

```
KnowledgeBase/
├── CLAUDE.md          # AI가 이 폴더를 읽는 법
├── 00.memory/tasks/   # 세션 기록 — 할 일 / 진행 중 / 완료 (예시 1개 포함)
├── 10.notes/          # 배움·조사·아이디어 (INDEX.md가 목차)
├── 20.work/           # 일·프로젝트 지식 — 회사 일, 사이드 프로젝트, 스터디 (INDEX.md가 목차)
├── 90.private/        # 개인 기록 — AI가 요청 없이 읽지 않음
└── _kit/              # 이 킷의 스킬·훅 (설치 시 자동 생성)
```

목차(INDEX) 관리와 폴더 정리는 AI가 규칙에 따라 알아서 합니다. 세션을 종료할 때마다 건강검진(lint)도 자동으로 돌아서 깨진 링크나 목차 누락을 그 자리에서 고칩니다.

## FAQ

**Q. 기록을 매번 남겨야 하나요?**
아니요. 남길 게 없는 세션은 그냥 닫아도 됩니다. "이건 다음에 이어서 해야 하는데" 싶은 세션만큼은 종료를 남기는 게 핵심 습관입니다.

**Q. 백업은 어떻게 하나요?**
vault는 평범한 폴더라서 컴퓨터가 고장 나면 같이 사라집니다. 가장 쉬운 방법은 Dropbox나 Google Drive 같은 **동기화 폴더 안에 vault를 만드는 것**입니다 — 설치할 때 AI에게 "vault를 Dropbox 안에 만들어서 설치해줘"라고 말하면 됩니다 (경로에 공백이 없어야 해서, 공백이 있는 iCloud 기본 경로는 지원하지 않습니다). git을 안다면 vault에서 git으로 관리하는 것도 좋습니다.

**Q. 민감정보 차단이 떴어요.**
저장하려는 기록에 이메일·전화번호·비밀번호 같은 게 들어 있다는 뜻입니다(Claude만 해당). 사람은 실명 대신 역할("담당자", "친구 A")로, 연락처는 지우거나 `010-0000-0000` 같은 명백한 예시값으로 바꾸면 통과됩니다. 남의 개인정보를 기록에 쌓지 않는 습관은 Codex를 쓸 때도 지키는 게 좋습니다.

**Q. 자동 로드가 안 되는 것 같아요. (Claude)**
AI에게 "session-context.sh 훅이 등록됐는지 확인해줘"라고 말하면 진단해줍니다. 훅 변경은 새 세션부터 적용된다는 점도 확인하세요.

**Q. 지우고 싶어요.**
AI에게 "이 킷의 uninstall.sh를 실행해줘"라고 말하면 스킬 연결과 훅 등록이 제거됩니다. vault는 그대로 남으니, 더 이상 필요 없으면 폴더째 지우면 됩니다.

**Q. 규칙을 바꾸고 싶어요.**
`vault/_kit/skills/` 안의 SKILL.md가 원본입니다. AI에게 "기록 양식에 ○○ 섹션 추가해줘"라고 시키면 됩니다. 단, 나중에 setup.sh를 다시 실행하면(킷 업데이트를 받을 때) 수정한 파일은 `.bak-{시각}`으로 백업된 뒤 킷 버전으로 교체되니, 수정 내용은 백업과 비교해 다시 반영하세요.

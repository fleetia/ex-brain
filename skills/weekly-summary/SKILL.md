# 주간 작업 요약

지식 vault(`~/KnowledgeBase`)의 태스크 기록을 모아 한 주 요약을 만든다. **사용자가 직접 요청할 때만 실행한다.**

## 실행 단계

1. **대상 기간 계산**: 가장 최근 완료된 월~일 한 주. 오늘이 월요일이면 어제(일요일)까지의 주. ISO 주차 번호(WNN)를 계산한다.

2. **태스크 수집**: `00.memory/tasks/{done,in-progress,todo}/*.md`를 스캔해 frontmatter `work-dates`에 대상 기간 날짜가 하나라도 포함된 파일을 모은다. `work-dates`가 없으면 `start`/`end` 범위가 겹치는지로 판단한다. 해당 파일이 없으면 "해당 주간 태스크가 없습니다"라고 알리고 종료한다.

3. **방치 태스크 정리 제안**: `in-progress/` 태스크 중 마지막 `work-dates`(없으면 파일 수정일)가 2주 이상 지난 것을 모아 보여주고, 실제로는 끝난 일이면 `done/` 이동을, 더 진행하지 않을 일이면 정리 여부를 사용자에게 확인한다. 확인 없이 이동·삭제하지 않는다. 남겨두기로 한 건은 요약의 "태스크 정리" 섹션에 사유와 함께 나열한다 (문서상 미완료가 실제 미완료라는 보장은 없다).

4. **기존 요약 확인**: `00.memory/weekly/YYYY-WNN.md`가 이미 있으면 덮어쓸지 확인한다.

5. **요약 작성**: 수집한 태스크 파일을 읽고 다음 구조로 쓴다.

   ```markdown
   # W{NN} 주간 요약 ({시작일} ~ {종료일})

   ## 주요 작업
   - {태스크들을 주제별로 그룹핑하여 요약}

   ## 태스크 상세
   ### {태스크 제목} ({status})
   - {해당 주에 수행한 작업 중심으로 압축}

   ## 다음 주로 넘어가는 일
   - {in-progress 태스크의 미완료 항목}
   ```

   - 기술적 세부사항보다 "무엇을 했고 무엇이 결정됐는지"에 초점을 둔다.
   - 여러 주에 걸친 태스크는 해당 주 작업분만 요약한다.

6. **반복 작업 한 줄 언급**: 여러 주에 걸쳐 같은 유형의 작업이 반복되는 게 보이면 요약 끝에 한 줄로 언급한다 (템플릿화·자동화 후보). 억지로 찾지 않는다.

7. **저장**: `00.memory/weekly/YYYY-WNN.md`에 저장하고 (폴더 없으면 생성) 경로와 포함 태스크 수를 보고한다.

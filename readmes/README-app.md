# AI 개발·세션 기록 킷

AI에게 한 번 질문하고 끝난다면 이 킷은 필요하지 않습니다. 앱이나 웹사이트를 만들고 고치는 일을 여러 대화에 걸쳐 이어간다면 필요해집니다.

AI는 코드를 만들 수 있어도 매번 같은 방식으로 일하지는 않습니다. 기술 선택을 사용자에게 넘기거나, "수정했다"와 "실제로 쓸 수 있다"를 섞어 말하거나, 새 대화에서 지난 결정을 놓칠 수 있습니다.

이 킷은 새 개발 AI를 설치하는 도구가 아닙니다. Claude Code나 Codex에 **일하는 규칙과 다음 대화용 인수인계 노트**를 붙입니다. 사용자는 원하는 결과를 말하고, AI는 기존 작업을 살펴본 뒤 확인 가능한 동작으로 정리합니다. 무엇을 실제로 바꾸고 확인했는지 알기 쉽게 설명하고, 세션을 마칠 때 직접 요청하거나 AI의 정리 제안에 동의하면 다음 대화에서 이어갈 기록을 내 컴퓨터에 남깁니다.

인수인계 노트가 수정한 코드 자체를 복사하는 것은 아닙니다. 아직 commit하지 않은 코드가 있으면 다음 대화가 같은 작업 폴더의 실제 변경을 확인해야 하며, 같은 project의 다른 작업 폴더에 코드가 있다고 가정하지 않습니다.

## 이런 일이 반복된다면 필요합니다

| 작업하는 순간 | 그냥 AI와 일할 때 생기는 문제 | 이 킷을 설치하면 |
|---|---|---|
| 원하는 결과를 말할 때 | "완료한 항목을 숨겨줘"라고 했는데 개발 도구나 저장 방식부터 선택해야 한다 | AI가 기존 작업을 먼저 살펴보고, 사용자가 확인할 수 있는 동작으로 요청을 정리한다 |
| "수정했습니다"라는 답을 받을 때 | 아이디어만 낸 것인지, 내 컴퓨터에 반영된 것인지, 확인이나 공개까지 끝난 것인지 알기 어렵다 | AI가 생각만 한 것, 실제로 바꾼 것, 확인한 것, 밖으로 전달한 것을 나눠 설명한다 |
| 다음 대화를 열 때 | 지난 결정, 실패한 시도, 남은 일을 처음부터 다시 설명한다 | 세션을 마칠 때 인수인계 기록을 남기고, 다음 대화에서 그 기록을 골라 이어간다 |

채팅 기록이 남아 있어도, 새 대화의 AI가 이전 결정과 현재 상태를 정확히 이어받는다는 보장은 없습니다. 이 킷은 첫 번째와 두 번째 문제를 AI의 작업 원칙으로 줄이고, 세 번째 문제는 내 컴퓨터에 남기는 인수인계 기록으로 줄입니다.

## 어떻게 동작하나

```
"만들어줘"·"고쳐줘"라고 원하는 결과를 말함
        │
        ▼
AI가 기존 작업을 확인하고 작은 범위로 수정·확인
        │
        ├─▶ 바꾼 것 · 확인한 것 · 아직 하지 않은 것을 구분해 설명
        │
        ▼
AI가 정리를 제안하거나 "세션 종료해줘"라고 말함
        │
        └─▶ 내 지식 폴더에 인수인계 기록
             (결정 · 검증 · 남은 일 · 실패한 시도)

다음 대화 ──▶ 진행 중 기록이 있는지만 안내 ──▶ "이어서 하자"
                                                  │
                                                  └─ 현재 project 기록과 실제 code state를 확인한 뒤 계속 작업
```

모든 대화가 저절로 기록되는 것은 아닙니다. 여러 단계가 쌓였고 기록과 실제 code state를 함께 이어갈 수 있는 지점이면 AI가 먼저 정리를 제안할 수 있습니다. 직접 마치고 싶을 때는 **"세션 종료해줘"**라고 말하면 됩니다. 다음 대화에서는 진행 중 기록의 개수만 먼저 보입니다. **"이어서 하자"**라고 하면 AI가 현재 project에 맞는 기록을 찾고, 수정한 코드가 실제로 있는지 확인한 뒤 작업을 계속합니다.

기록은 `~/KnowledgeBase`(이하 vault)라는 폴더에 평범한 markdown 파일로 쌓입니다. 메모 앱(Obsidian 등)으로 열어봐도 되고, 그냥 폴더로 둬도 됩니다.

## 이 킷을 설치하면 AI가 따르는 작업 원칙

개발 용어로 사양서를 먼저 쓸 필요는 없습니다. "이 목록에서 완료한 항목을 숨길 수 있게 해줘", "버튼을 눌러도 아무 일도 안 일어나는데 고쳐줘"처럼 보이는 결과나 문제를 말하면 됩니다.

AI는 다음 원칙으로 작업합니다.

1. 확인할 수 있는 기존 작업과 현재 동작을 먼저 살펴보고, 요청을 사용자가 판단할 수 있는 동작으로 정리합니다.
2. 기존 구조 안에서 정할 수 있는 기술적인 세부 사항은 AI가 처리합니다. 화면 동작, 데이터, 비용처럼 결과가 달라지는 선택만 권장안과 함께 묻습니다.
3. "만들어줘", "고쳐줘" 같은 구현 요청에는 요청 범위의 local 파일 수정과 관련 검증까지 포함합니다. 외부 package 추가, 삭제, commit·push, deploy·publish, 외부 전송은 별도 승인을 받습니다.
4. 결과를 `제안`(방향만 정함), `구현`(local 파일을 바꿈), `검증`(밝힌 범위에서 확인함), `전달`(외부 공개까지 확인함)로 구분합니다. test 통과만으로 실제 화면이나 배포까지 확인했다고 말하지 않습니다.

## 개발할 때는 이렇게 말하면 됩니다

Skill 이름이나 command를 외울 필요는 없습니다. 평소 말하듯 요청하면 상황에 맞는 개발 skill이 함께 적용됩니다.

| 이렇게 말하면 | AI가 하는 일 |
|---|---|
| "완료한 항목을 숨길 수 있게 해줘" | 원하는 결과를 확인 가능한 동작으로 정리하고 작은 범위로 구현합니다 |
| "이거 실행해서 어디서 보는지 알려줘" | project가 제공하는 방법으로 local 실행하고, 열 주소와 종료 방법을 알려줍니다 |
| "버튼을 눌러도 아무 일도 안 일어나. 고쳐줘" | 같은 문제를 재현하고 전체 흐름에서 원인을 확인한 뒤 최소 범위로 고칩니다 |
| "이제 정말 다 된 거야? 보내도 돼?" | 실제로 확인된 것, 확인하지 못한 것, 공개 전에 남은 위험을 나눠 알려줍니다 |

## 준비물

- **Claude Code 또는 Codex** — 내 컴퓨터의 파일을 만들고 고칠 수 있는 로컬 agent가 필요합니다. 웹 브라우저 전용 챗에는 설치할 수 없습니다.
- **macOS, Linux 또는 Windows** — native Windows는 Windows PowerShell 5.1 이상을 사용하며 Codex에서는 Windows 11을 권장합니다. Claude Code의 Bash 기능을 함께 쓰고 싶다면 Git for Windows를 추가할 수 있지만, 이 킷 설치에는 필요하지 않습니다.
- macOS·Linux·WSL은 `bash`와 `jq`가 필요합니다. macOS에 `jq`가 없다면 `brew install jq`로 설치할 수 있습니다. Python 3는 vault lint에만 필요하므로 없어도 기록·복원 기능은 동작합니다. native Windows PowerShell판은 내장 JSON 기능을 사용하므로 `jq`가 필요 없습니다.

## 설치

가장 쉬운 방법은 **AI에게 시키는 것**입니다.

1. 이 폴더(압축을 받았다면 푼 폴더)를 AI 앱에서 엽니다
2. macOS·Linux에서는 **"이 폴더의 setup.sh를 실행해서 킷을 설치해줘"**, Windows에서는 **"이 폴더의 setup.ps1을 PowerShell로 실행해서 킷을 설치해줘"**라고 말합니다
3. 설치가 끝나면 새 세션을 엽니다. Claude는 바로 동작하고, Codex는 `/hooks`에서 새 훅을 검토해 신뢰한 뒤 동작합니다

터미널이 익숙하면 macOS·Linux에서 `bash setup.sh`, Windows PowerShell에서 `powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1`을 직접 실행해도 됩니다. WSL과 native Windows는 설정이 분리되어 있으므로 실제로 agent를 실행할 환경에서 각각 설치합니다. 실행이 멈추면 AI에게 로그를 보여주고 원인을 진단해 달라고 하세요. JSON이나 지원 환경 문제를 고친 뒤 같은 설치 스크립트를 다시 실행해야 ownership 확인과 실패 복구가 유지됩니다.

여러 번 설치해도 안전합니다. 이미 있는 vault에는 빠진 기본 폴더·파일만 추가하고 기존 문서는 덮어쓰지 않습니다. 구버전이 배포한 기본 `AGENTS.md`·`CLAUDE.md`를 수정 없이 쓰고 있었다면 새 privacy 규칙으로 갱신하고 먼저 backup을 남깁니다. 다른 도구가 만든 skill 연결이나 폴더와 충돌하면 그대로 보존하고 설치를 멈춥니다. Windows의 skill 연결은 관리자 권한이 필요 없는 directory junction을 사용합니다. 올바른 JSON에 등록된 다른 hook은 지우지 않고 함께 유지합니다.

실행되는 스킬·훅·lint는 동기화 폴더 밖인 `~/.ai-session-kit/runtime/`에 설치됩니다. vault에는 내 markdown 기록만 둬서, 동기화된 파일이 곧바로 local script로 실행되지 않게 분리합니다.

## Claude와 Codex의 차이

스킬과 자동 실행 훅은 양쪽에 연결됩니다. Codex는 안전을 위해 설치되거나 바뀐 command hook을 처음 한 번 직접 신뢰해야 합니다.

| | Claude | Codex |
|---|---|---|
| "세션 종료해줘"로 기록 | ✓ | ✓ |
| "이어서 하자"로 복원 | ✓ | ✓ |
| 세션 시작 시 진행 중 기록 여부 자동 안내 | ✓ | ✓ — `/hooks`에서 신뢰 후 |
| 지원되는 쓰기 작업의 민감정보 사전 검사 | ✓ | ✓ — `/hooks`에서 신뢰 후 |

## 일상 사용법

직접 외울 것은 하나뿐입니다. **원할 때 "세션 종료해줘"라고 말하기.** 긴 작업에서는 AI가 안전하게 끊을 수 있는 지점에서 먼저 제안할 수도 있습니다.

- **세션 종료**: "세션 종료해줘" → 오늘 한 일, 남은 일, 시도했다가 접은 것까지 기록됩니다
- **세션 시작**: 진행 중 기록의 개수만 자동으로 뜹니다. "이어서 하자" → 현재 project의 기록과 실제 code state를 확인하고 이어갑니다
- **새 작업**: 자동입니다. AI가 착수 전에 과거 기록을 먼저 검색해서, 예전에 내린 결정이나 했던 조사를 반영합니다
- **개발 작업**: 원하는 결과를 일상어로 말합니다. 구현을 요청하면 AI가 기존 project를 확인하고 요청 범위의 작은 local 구현과 관련 검증까지 진행합니다
- **세션 전환 제안**: 여러 단계가 쌓이고 기록과 실제 code state를 안전하게 넘길 수 있으면 AI가 한 번 정리를 제안합니다. 동의하기 전에는 기록하지 않습니다
- **주간·월간 돌아보기**: 원할 때 "주간 요약 만들어줘" / "월간 요약 만들어줘"라고 하면 그동안의 기록을 모아 정리해줍니다. 자동으로 돌지 않습니다

## 무엇이 설치되나

| 종류 | 이름 | 역할 |
|---|---|---|
| 스킬 | `session-end` | 세션 종료 시 한 일·남은 일·과정 메모를 기록 |
| 스킬 | `session-start` | 이전 기록을 읽고 이어서 시작 |
| 스킬 | `kb-lookup` | 새 작업 전에 과거 기록을 먼저 검색 |
| 스킬 | `kb-routing` | 기록을 어느 폴더에 둘지, 목차를 어떻게 관리할지 규칙 |
| 스킬 | `guided-development` | 제품 결과 중심 요청을 작은 local 구현·검증과 쉬운 결과 설명으로 연결 |
| 스킬 | `guided-debugging` | 구체적인 오작동을 재현하고 전체 흐름에서 원인을 찾아 최소 수정·재검증 |
| 스킬 | `project-run-and-preview` | project 고유 방법으로 local 실행하고 실제 미리보기와 종료 방법 안내 |
| 스킬 | `change-verification` | 변경 뒤 확인된 것·미확인 상태·외부 전달 상태를 evidence로 구분 |
| 스킬 | `weekly-summary` / `monthly-summary` | 주간·월간 요약 — **요청할 때만** |
| 스킬 | `humanize-ko` | 한국어 글의 번역투·상투 표현을 자연스럽게 다듬기 |
| 스킬 | `cognitive-rhythm-writing` | 긴 설명글·블로그 글에 강약과 호흡 만들기 |
| 스킬 | `task-doc-writing` | 여럿이 함께 읽는 작업 문서를 이해하기 쉬운 서술형으로 |
| 훅 (Claude·Codex) | `session-context.sh` / `.ps1` | 세션이 열릴 때 파일명 없이 진행 중 기록·최근 문서의 개수와 vault 상태만 안내 |
| 훅 (Claude·Codex) | `check-pii.sh` / `.ps1` | 지원되는 파일 쓰기 전에 이메일·전화번호·비밀번호류를 검사 |
| 스크립트 | `kb_lint.py` | 기록 폴더 건강검진 — 깨진 링크, 목차 누락 등 |

스킬은 AI가 상황에 맞게 알아서 참고하는 지침서입니다. 설치된 사본은 `~/.ai-session-kit/runtime/`에 있고 setup.sh 또는 setup.ps1이 관리합니다.

## vault(지식 폴더) 구조

```
KnowledgeBase/
├── CLAUDE.md          # Claude가 이 폴더를 읽는 법
├── AGENTS.md          # Codex가 이 폴더를 읽는 법
├── 00.memory/tasks/   # 세션 기록 — todo / in-progress / done / cancelled
├── 10.notes/          # 배움·조사·아이디어 (INDEX.md가 목차)
├── 20.work/           # 일·프로젝트 지식 — 회사 일, 사이드 프로젝트, 스터디 (INDEX.md가 목차)
└── 90.private/        # 개인 기록 — AI가 요청 없이 읽지 않음
```

구버전 설치에서 남은 `vault/_kit/`은 자동 삭제하지 않지만, 업데이트 뒤에는 hook이나 global skill 경로로 실행하지 않습니다.

목차(INDEX) 관리와 폴더 정리는 AI가 규칙에 따라 알아서 합니다. 세션을 종료할 때마다 건강검진(lint)도 자동으로 돌아서 깨진 링크나 목차 누락을 그 자리에서 고칩니다.

## FAQ

**Q. 기록을 매번 남겨야 하나요?**
아니요. 남길 게 없는 세션은 그냥 닫아도 됩니다. "이건 다음에 이어서 해야 하는데" 싶은 세션만큼은 종료를 남기는 게 핵심 습관입니다.

**Q. 백업은 어떻게 하나요?**
vault는 평범한 폴더라서 컴퓨터가 고장 나면 같이 사라집니다. 가장 쉬운 방법은 Dropbox, OneDrive, iCloud Drive 같은 **내 계정의 비공개 동기화 폴더 안에 vault를 만드는 것**입니다. 경로에 공백이 있어도 됩니다. AGENTS.md와 CLAUDE.md는 AI가 읽는 지침 파일이므로, 모르는 사람이 쓸 수 있는 공유 폴더나 public 저장소에는 vault를 두지 마세요. 동기화가 끝나기 전에 두 컴퓨터에서 같은 파일을 동시에 고치면 충돌 사본이 생길 수 있습니다. git을 안다면 private 저장소로 관리해도 좋습니다.

**Q. 민감정보 차단이 떴어요.**
지원되는 파일 쓰기 요청에 이메일·전화번호·비밀번호 같은 패턴이 들어 있다는 뜻입니다. 사람은 실명 대신 역할("담당자", "친구 A")로, 연락처는 지우거나 `010-0000-0000` 같은 명백한 예시값으로 바꾸면 통과됩니다.

이 검사는 보조장치입니다. Claude의 Write/Edit와 Codex의 apply_patch처럼 훅이 지원하는 쓰기 도구는 파일명과 저장 결과를 미리 검사합니다. SessionStart에서는 project를 확인하기 전 문서 파일명을 넣지 않고 개수만 보여줍니다. 다만 shell redirect, 일부 MCP, 다른 편집기에서 직접 쓴 내용까지 모두 막는 개인정보 보호 솔루션은 아닙니다. 감지 결과에도 원문 secret은 출력하지 않습니다.

**Q. "이어서 하자"고 했는데 수정한 코드가 안 보여요.**
인수인계 기록과 code는 따로 있습니다. commit하지 않은 변경은 원래 작업 폴더에만 있을 수 있습니다. AI가 기록한 기준 commit과 현재 변경을 먼저 비교하고, 다르면 코드를 다시 만들지 않고 원래 작업 폴더를 열지 안전하게 옮길지 물어봅니다.

**Q. 자동 로드가 안 되는 것 같아요. (Claude)**
AI에게 "session-context 훅이 등록됐는지 확인해줘"라고 말하면 진단해줍니다. 훅 변경은 새 세션부터 적용된다는 점도 확인하세요.

**Q. 자동 로드가 안 되는 것 같아요. (Codex)**
Codex에서 `/hooks`를 열어 `session-context`와 `check-pii` hook을 검토하고 신뢰했는지 확인하세요. Windows에서는 `commandWindows`가 등록됩니다. 설치나 업데이트로 command가 바뀌면 다시 검토해야 합니다.

**Q. 지우고 싶어요.**
macOS·Linux에서는 AI에게 "이 킷의 uninstall.sh를 실행해줘", Windows에서는 "uninstall.ps1을 PowerShell로 실행해줘"라고 말하면 스킬 연결과 훅 등록이 제거됩니다. vault는 그대로 남으니, 더 이상 필요 없으면 폴더째 지우면 됩니다.

**Q. 규칙을 바꾸고 싶어요.**
배포받아 푼 원본 폴더의 `skills/`를 수정한 뒤 운영체제에 맞는 setup.sh 또는 setup.ps1을 다시 실행합니다. `~/.ai-session-kit/runtime/`은 installer가 교체하는 설치 사본이므로 직접 수정하지 않습니다. AI에게 원본 폴더를 보여주고 "session-end 스킬에 ○○ 섹션을 추가한 뒤 다시 설치해줘"라고 시키면 됩니다.

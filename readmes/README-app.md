# AI 세션 기록 킷

AI 앱(Claude, Codex)과 함께한 작업이 대화창을 닫아도 사라지지 않게 만드는 킷입니다. 세션을 마칠 때 한 마디로 기록을 남기고, 다음 세션이 그 기록을 이어받습니다.

## 왜 필요한가

AI와 일하다 보면 이런 일이 반복됩니다.

- 지난주에 AI와 한참 정리했던 내용을, 새 대화창에서 처음부터 다시 설명하고 있다
- 같은 조사를 또 시키고, 이미 내렸던 결정을 또 고민한다
- "어디까지 했더라?"로 매번 시작한다

대화창이 닫히는 순간 그 안의 맥락은 사라집니다. 이 킷은 **작업을 세션 단위로 기록하고, 다음 세션이 그 기록에서 시작하는 구조**를 만듭니다. 회사 일이든 사이드 프로젝트든 블로그든, "지난번에 뭘 했더라?"가 사라집니다.

## 어떻게 동작하나

```
AI와 작업 ──▶ "세션 종료해줘" ──▶ 내 지식 폴더에 기록
                                   (한 일 · 남은 일 · 과정 메모)

다음 세션 ──▶ "이어서 하자" ──▶ 기록을 읽고 이어서 진행
                │
                └─ 새 작업을 시작하면 과거 기록을 먼저 검색해서 반영
```

기록은 `~/KnowledgeBase`(이하 vault)라는 폴더에 평범한 markdown 파일로 쌓입니다. 메모 앱(Obsidian 등)으로 열어봐도 되고, 그냥 폴더로 둬도 됩니다.

## 준비물

- **Claude Code 또는 Codex** — 내 컴퓨터의 파일을 만들고 고칠 수 있는 로컬 agent가 필요합니다. 웹 브라우저 전용 챗에는 설치할 수 없습니다.
- **macOS 또는 Linux** — 설치 스크립트는 Bash와 symlink를 사용합니다. Windows에서는 WSL 안에 설치할 수 있지만, 그 설정은 WSL 안에서 실행한 agent에만 적용됩니다. native Windows 앱 설치는 아직 지원하지 않습니다.
- `bash` — 설치와 업데이트에 필요합니다.
- `jq` — 기존 앱 설정에 훅을 안전하게 합치고, 민감정보 검사를 켜는 데 필요합니다. 없으면 설정을 건드리지 않고 설치 활성화를 멈추므로, `jq`를 설치한 뒤 setup.sh를 다시 실행합니다.

## 설치

가장 쉬운 방법은 **AI에게 시키는 것**입니다.

1. 이 폴더(압축을 받았다면 푼 폴더)를 AI 앱에서 엽니다
2. 이렇게 말합니다: **"이 폴더의 setup.sh를 실행해서 킷을 설치해줘"**
3. 설치가 끝나면 새 세션을 엽니다. Claude는 바로 동작하고, Codex는 `/hooks`에서 새 훅을 검토해 신뢰한 뒤 동작합니다

터미널이 익숙하면 직접 `bash setup.sh`를 실행해도 됩니다. 실행이 멈추면 AI에게 로그를 보여주고 원인을 진단해 달라고 하세요. `jq`, JSON, 지원 환경 문제를 고친 뒤 같은 setup.sh를 다시 실행해야 ownership 확인과 실패 복구가 유지됩니다.

여러 번 설치해도 안전합니다. 이미 있는 vault에는 빠진 기본 폴더·파일만 추가하고 기존 문서는 덮어쓰지 않습니다. 구버전이 배포한 기본 CLAUDE.md를 수정 없이 쓰고 있었다면 새 privacy 규칙으로 갱신하고 먼저 backup을 남깁니다. 다른 도구가 만든 skill symlink나 폴더와 충돌하면 그대로 보존하고 설치를 멈춥니다. 올바른 JSON에 등록된 다른 hook은 지우지 않고 함께 유지합니다.

실행되는 스킬·훅·lint는 동기화 폴더 밖인 `~/.ai-session-kit/runtime/`에 설치됩니다. vault에는 내 markdown 기록만 둬서, 동기화된 파일이 곧바로 local script로 실행되지 않게 분리합니다.

## Claude와 Codex의 차이

스킬과 자동 실행 훅은 양쪽에 연결됩니다. Codex는 안전을 위해 설치되거나 바뀐 command hook을 처음 한 번 직접 신뢰해야 합니다.

| | Claude | Codex |
|---|---|---|
| "세션 종료해줘"로 기록 | ✓ | ✓ |
| "이어서 하자"로 복원 | ✓ | ✓ |
| 세션 시작 시 진행 중 작업 자동 로드 | ✓ | ✓ — `/hooks`에서 신뢰 후 |
| 지원되는 쓰기 작업의 민감정보 사전 검사 | ✓ | ✓ — `/hooks`에서 신뢰 후 |

## 일상 사용법

외울 것은 하나뿐입니다. **세션을 마칠 때 "세션 종료해줘"라고 말하기.**

- **세션 종료**: "세션 종료해줘" → 오늘 한 일, 남은 일, 시도했다가 접은 것까지 기록됩니다
- **세션 시작**: 진행 중 작업 목록이 자동으로 먼저 뜹니다. "이어서 하자" → 지난 기록을 읽고 이어갑니다
- **새 작업**: 자동입니다. AI가 착수 전에 과거 기록을 먼저 검색해서, 예전에 내린 결정이나 했던 조사를 반영합니다
- **주간·월간 돌아보기**: 원할 때 "주간 요약 만들어줘" / "월간 요약 만들어줘"라고 하면 그동안의 기록을 모아 정리해줍니다. 자동으로 돌지 않습니다

## 무엇이 설치되나

| 종류 | 이름 | 역할 |
|---|---|---|
| 스킬 | `session-end` | 세션 종료 시 한 일·남은 일·과정 메모를 기록 |
| 스킬 | `session-start` | 이전 기록을 읽고 이어서 시작 |
| 스킬 | `kb-lookup` | 새 작업 전에 과거 기록을 먼저 검색 |
| 스킬 | `kb-routing` | 기록을 어느 폴더에 둘지, 목차를 어떻게 관리할지 규칙 |
| 스킬 | `weekly-summary` / `monthly-summary` | 주간·월간 요약 — **요청할 때만** |
| 스킬 | `humanize-ko` | 한국어 글의 번역투·상투 표현을 자연스럽게 다듬기 |
| 스킬 | `cognitive-rhythm-writing` | 긴 설명글·블로그 글에 강약과 호흡 만들기 |
| 스킬 | `task-doc-writing` | 여럿이 함께 읽는 작업 문서를 이해하기 쉬운 서술형으로 |
| 훅 (Claude·Codex) | `session-context.sh` | 세션이 열릴 때 진행 중 작업·최근 문서를 자동으로 보여줌 |
| 훅 (Claude·Codex) | `check-pii.sh` | 지원되는 파일 쓰기 전에 이메일·전화번호·비밀번호류를 검사 |
| 스크립트 | `kb_lint.py` | 기록 폴더 건강검진 — 깨진 링크, 목차 누락 등 |

스킬은 AI가 상황에 맞게 알아서 참고하는 지침서입니다. 설치된 사본은 `~/.ai-session-kit/runtime/`에 있고 setup.sh가 관리합니다.

## vault(지식 폴더) 구조

```
KnowledgeBase/
├── CLAUDE.md          # Claude가 이 폴더를 읽는 법
├── AGENTS.md          # Codex가 이 폴더를 읽는 법
├── 00.memory/tasks/   # 세션 기록 — todo / in-progress / done / cancelled
├── 10.notes/          # 배움·조사·아이디어 (INDEX.md가 목차)
├── 20.work/           # 일·프로젝트 지식 — 회사 일, 사이드 프로젝트, 스터디 (INDEX.md가 목차)
└── 90.private/        # 개인 기록 — AI가 요청 없이 읽지 않음
```

구버전 설치에서 남은 `vault/_kit/`은 자동 삭제하지 않지만, 업데이트 뒤에는 hook이나 global skill 경로로 실행하지 않습니다.

목차(INDEX) 관리와 폴더 정리는 AI가 규칙에 따라 알아서 합니다. 세션을 종료할 때마다 건강검진(lint)도 자동으로 돌아서 깨진 링크나 목차 누락을 그 자리에서 고칩니다.

## FAQ

**Q. 기록을 매번 남겨야 하나요?**
아니요. 남길 게 없는 세션은 그냥 닫아도 됩니다. "이건 다음에 이어서 해야 하는데" 싶은 세션만큼은 종료를 남기는 게 핵심 습관입니다.

**Q. 백업은 어떻게 하나요?**
vault는 평범한 폴더라서 컴퓨터가 고장 나면 같이 사라집니다. 가장 쉬운 방법은 Dropbox, OneDrive, iCloud Drive 같은 **내 계정의 비공개 동기화 폴더 안에 vault를 만드는 것**입니다. 경로에 공백이 있어도 됩니다. AGENTS.md와 CLAUDE.md는 AI가 읽는 지침 파일이므로, 모르는 사람이 쓸 수 있는 공유 폴더나 public 저장소에는 vault를 두지 마세요. 동기화가 끝나기 전에 두 컴퓨터에서 같은 파일을 동시에 고치면 충돌 사본이 생길 수 있습니다. git을 안다면 private 저장소로 관리해도 좋습니다.

**Q. 민감정보 차단이 떴어요.**
지원되는 파일 쓰기 요청에 이메일·전화번호·비밀번호 같은 패턴이 들어 있다는 뜻입니다. 사람은 실명 대신 역할("담당자", "친구 A")로, 연락처는 지우거나 `010-0000-0000` 같은 명백한 예시값으로 바꾸면 통과됩니다.

이 검사는 보조장치입니다. Claude의 Write/Edit와 Codex의 apply_patch처럼 훅이 지원하는 쓰기 도구는 파일명과 저장 결과를 미리 검사합니다. 이미 존재하는 문서의 파일명에 민감정보가 보이면 SessionStart 목록에서는 원문을 숨깁니다. 다만 shell redirect, 일부 MCP, 다른 편집기에서 직접 쓴 내용까지 모두 막는 개인정보 보호 솔루션은 아닙니다. 감지 결과에도 원문 secret은 출력하지 않습니다.

**Q. 자동 로드가 안 되는 것 같아요. (Claude)**
AI에게 "session-context.sh 훅이 등록됐는지 확인해줘"라고 말하면 진단해줍니다. 훅 변경은 새 세션부터 적용된다는 점도 확인하세요.

**Q. 자동 로드가 안 되는 것 같아요. (Codex)**
Codex에서 `/hooks`를 열어 `session-context.sh`와 `check-pii.sh`를 검토하고 신뢰했는지 확인하세요. 설치나 업데이트로 command가 바뀌면 다시 검토해야 합니다.

**Q. 지우고 싶어요.**
AI에게 "이 킷의 uninstall.sh를 실행해줘"라고 말하면 스킬 연결과 훅 등록이 제거됩니다. vault는 그대로 남으니, 더 이상 필요 없으면 폴더째 지우면 됩니다.

**Q. 규칙을 바꾸고 싶어요.**
배포받아 푼 원본 폴더의 `skills/`를 수정한 뒤 setup.sh를 다시 실행합니다. `~/.ai-session-kit/runtime/`은 installer가 교체하는 설치 사본이므로 직접 수정하지 않습니다. AI에게 원본 폴더를 보여주고 "session-end 스킬에 ○○ 섹션을 추가한 뒤 다시 설치해줘"라고 시키면 됩니다.
